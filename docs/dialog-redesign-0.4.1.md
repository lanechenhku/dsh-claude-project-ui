## 1. 置顶问题：根因与修法

**旧做法**：弹窗是 `position: fixed` + `z-index: 9999`，直接渲染在 `shell.overlay` 槽位里。

**根因**：只要任何一级祖先带 `transform` / `filter` / `backdrop-filter` / `contain` / `isolation`，
就会新建一个**层叠上下文**。`position: fixed` 元素被这个上下文捕获后，`z-index: 9999` 只在这个上下文
*内部*参与排序，于是一个 `z-index: 1` 的宿主层在外部就能压住它。调高数字没有用。

**现在**：弹窗走 React portal，挂到 `document.body` 下的专用容器 `#project-hub-dialog-root`：

- 容器带 `role="dialog"`、`aria-modal="true"`、`aria-labelledby` 指向弹窗标题节点；
- 容器只创建一次（按 id 复用），重复打开不会叠加；
- 拿不到 `react-dom` 或没有 `document` 时退回原地渲染，弹窗不会消失；
- 打开时锁 `document.body` 滚动（关闭时恢复原值）；**Esc** 关闭；**点遮罩**关闭；右上 `✕` 关闭。

三个入口（看板 A / 设置页 B / 注入按钮 C）走的都是同一个 `FolderDialog`，所以修一次三处都修好。

## 3. 英文与语言切换

- 弹窗新增文案（「当前主文件夹 / Current main folder」「更换… / Change…」「手动输入路径 / Type a path」
  「辅助文件夹 / Auxiliary folders」「已保存 / Saved」「还不是…」等）zh/en **同时补齐**；
  两张表各 79 个 key，测试校验 key 集合完全一致、无空文案、且没有「表里有但没地方显示」的 key。
- 语言来源是 DSH 的 locale 服务，并且**两条线都订阅**：`ctx.on("locale/change")` 事件 + 
  `locale.subscribe(…)` 快照订阅。不是挂载时读一次 `<html lang>`。
- 代码层验证（`test/client-checks.mjs`）：模拟服务把 active 从 `en` 切到 `zh` 后，
  `langStore` 立即变成 `zh`、设置页分节标题 thunk 从 `Project folders` 变成 `项目文件夹`、
  弹窗文案 `dialog.saved` 变成「已保存」。这就是「切换语言会重渲染」的证据（真机视觉仍待看，见下）。

**一步操作（人来做）**：侧栏底部「设置」→「通用」→「语言」那一行 → 选 `English`。
语言行由 `dsh-client-locale` 提供，切完不用刷新。

## 5. 只能真机验的项

1. **弹窗是否真的在最上层**：portal + body 容器在代码层能证明「不在宿主层叠上下文里」，
   但「肉眼看上去压不压得住」要重启后从三个入口各开一次看（看板 A / 设置页 B / dsh-threads 注入按钮 C）。
2. **遮罩透明度与深浅主题**：`Canvas` 系统色 + 32% 黑遮罩在两套主题下的观感。
3. **锁滚动的可感知性**：弹窗打开时背景不滚，关闭后恢复；需要真机滚一下确认。
4. **Esc 与点遮罩**：事件监听是 `document` 级别（capture），但如果宿主在弹窗层级上再套一层 modal
   并拦截键盘，需要确认 Esc 仍能到达。
5. **「已保存」的位置**：确认它在行右端而不是换行到第二行（窄侧栏下需要看一眼）。
6. **英文整体观感**：切成 English 后弹窗、面板、设置页三段文案是否都不溢出（英文更长）。
