## 1. 看板版式（分区 / 间距 / 配色）

### 分区（从上到下）

| 区块 | 结构 | 说明 |
| --- | --- | --- |
| 面板头 | 标题 + 「刷新」 | 固定不滚 |
| 当前项目卡 | 3px 强调竖条 + 〔名称 / 11px mono 路径 / 计数 + 最近活动〕 + 〔切换文件夹⋯ / ▾〕 + 辅助文件夹折叠区 + 讨论串/任务行 | 一张带 hairline 的独立卡片；默认展开 |
| 分隔条（吸顶） | 2px 粗线 + 小号大写标签「其他项目 · N」 | `position: sticky; top: 0`，滚动时压在内容上方 |
| 其他项目卡 ×N | 紧凑行（▸ 名称 + 讨论串/任务计数 + 最近活动），点开才出讨论串/任务行 | 按最近活动倒序 |

「当前项目」= 打开面板时所在对话所属的项目：面板把自己所在会话的 `sessionId` POST 给宿主，
宿主用 `ProjectRegistry.roleOf(sessionId)` 解析成 `currentProjectId`。解析不出来（没有会话 / 会话不属于任何项目）
就不置顶，分隔条改显示「项目 · N」，整列按活跃度排。

### 间距（8px 网格）

- 结构节奏：`8 / 12 / 16 / 24`（面板内边距 8、头部 8×12、卡片内 12、块间距 12/16、底部 24）。
- 行内边距 `4px 8px`，行内 gap 8，按钮内边距 `4px 8px`，输入框 `4px 8px`。
- 卡片次级分隔 = `1px hairline + 12px paddingTop`（不多给 margin，避免两个来源的间距打架）。
- 讨论串/任务小节标签上下 `12 / 4`。

### 配色（深浅两套都读得出来）

| 用途 | 值 |
| --- | --- |
| 边框 | `rgba(127,127,127,0.18)`（强调边框 0.26） |
| hover 背景 | `rgba(127,127,127,0.06)` |
| 圆角 | 10（按钮/输入 8，弹窗 12） |
| 阴影 | **不使用**（弹窗只有半透明遮罩） |
| 字号 | 正文 12/13；路径 monospace 11 |
| 状态点 6px | 进行中 `#4C8DFF` · 待办 `#9AA0A6` · 受阻/待决策 `#E08A2E` · 已完成/已解决 `#3FAE6A` · 空闲/已停止 `#C6C9CD` |
| 提示/告警/错误 | 绿 `#3FAE6A` · 橙 `#E08A2E` · 红 `#E86A6A` |

强调竖条与「进行中」用同一个蓝（`#4C8DFF`），所以「当前项目」和「正在跑」在视觉上是一族。
吸顶条与弹窗用 CSS 系统色 `Canvas` / `CanvasText`：DSH 会在 `<html>` 上写 `color-scheme`，
系统色自动跟随深浅主题，不需要自己猜背景色。

### 行级细节

- 讨论串行：`● #12 标题……（单行省略，title 有全文） 待决策`。
- 任务行：`[进行中] b-3 主题……（右侧 + 复制任务号）`；`+` 复制的是 `b-3`，配合 `/hub done b-3`。
- 空状态：一行 `opacity: .42` 的 12px 提示，不占整块。
- 已解决/已归档：卡片内一行「另有 N 个已解决/已归档的讨论串」。

## 2. 三个入口

| 入口 | 触发 | 落到 |
| --- | --- | --- |
| A 看板 | 当前项目卡「切换文件夹⋯」→ 共用弹窗；卡片内「辅助文件夹」折叠区直接增删 | `POST /project-hub/folders` |
| B 设置页 | `slots.inject("settings.section")` 的「项目文件夹」分节，逐行「修改」 | 同上 |
| C dsh-threads | 注入的「⚙ 更多文件夹⋯」→ 同一个弹窗 | 同上 |

三者共用：`FolderForm`（文件夹表单）+ `FolderDialog`（`shell.overlay` 里挂一次）+ `src/mainfolder.js`（唯一写入路径）。
B 页没有「批量改全部」，只有逐行；被项目占用的工作区拒绝单独改（两处记录必须一起动）。

## 3. 双语

- 字典：`src/client.js` 的 `MESSAGES.zh` / `MESSAGES.en`，各 93 个 key，覆盖面板、弹窗、设置页、注入按钮。
- 语言源：`ctx.locale.getLocale().active` + `ctx.on("locale/change")`；字典同时用 `ctx.locale.register("project-hub", …)` 登记。
- 回退：当前语言 → 英文 → 中文 → key（测试覆盖「只有英文有」的情况）。
- 客户端 `inject` 因此新增 `locale`：没有该服务的 profile 不再挂载浏览器半（拿不到应用语言就别假装跟随）。

## 5. 未验证（需要人工看一眼）

1. **真机视觉**：没有重启 app，所以新版面板没有在真实 DSH 窗口里渲染过；吸顶条与滚动的叠加、
   深浅主题下 `Canvas` 与 DSH 侧栏背景是否完全同色、弹窗遮罩的层级是否压过 dsh-threads 自己的 Modal，
   都需要重启后目测。
2. **C 的真机注入**：`MutationObserver` 与按钮外观只在假 DOM 里验过；真实 dsh-threads 设置弹窗里
   按钮的位置/样式、React 重渲染时按钮是否被回收后重新注入，需要在真机上打开「项目设置 → 通用」确认。
3. **会话 id 来源**：`conversation.session.header.actions` 的 `sessionId` prop 依据上游 `PropsRuntime` 约定，
   没有在真机上验证「当前项目」一定命中；命中不了时面板会退回「不置顶 + 全部按活跃度排」，不会出错。
4. **侧栏页签标题跟随语言**：宿主渲染的 tab 标题是 thunk，宿主下次渲染才更新；没验证切语言时它即时刷新。

## 6. 设置入口（⚙，0.4.1 补）

看板头部「刷新」左边多了一个 **⚙**：点开是**同一套 portal** 里的紧凑面板（宽 360，锚在按钮下方、右边缘对齐），
不是全屏弹窗。

| 行 | 控件 | 默认 | 作用 |
| --- | --- | --- | --- |
| 语言 | 三选 segmented（跟随应用（中文）/ 中文 / English） | 跟随应用 | 手动选择优先于应用语言；选「跟随应用」时才走 locale 服务 |
| 显示已解决 / 已归档的讨论串 | 开关 | 关 | 宿主侧过滤：面板快照与注入的看板文本都不再列出它们 |
| 自动把讨论串回报汇总成任务 | 开关 | 开 | 宿主侧行为：关掉后 sweep 不再把回报写成看板任务 |
| 「其他项目」卡片 | 二选（默认折叠 / 默认展开） | 默认折叠 | 纯展示：非当前项目卡的初始展开状态 |
| 排序 | 二选（最近活动 / 名称） | 最近活动 | 纯展示：当前项目仍置顶，其余按所选顺序 |
| 项目文件夹管理… | 链接 | — | 打开统一管理页（复用设置页那个 `SettingsSection` 组件，见下） |

- **存储**：`<dataDir>/settings.json`（默认 `~/.dsh/project-hub/settings.json`），本插件自己的文件；
  **不写** dsh-threads 的 `dsh_threads.json`。宿主半的 `loadSettings/saveSettings`
  （`src/settings.js`）负责归一化与串行写，越界值（未知语言、未知排序）会被夹回默认。
- **生效**：客户端 store 改完立刻重渲染，同时 POST `/project-hub/settings` 持久化；
  宿主半下一次快照就用新值。其中「隐藏讨论串」和「回报汇总」是**宿主侧**行为
  （快照过滤 + sweep），不是前端假装，所以两侧都必须读同一份文件——测试覆盖了这一点。
- **语言优先级**：`手动 zh/en > locale 服务 > 页面 <html lang>/navigator > en`。
  「跟随应用（中文）」括号里显示的是**当前应用语言**的名字，切应用语言时它跟着变。
- **管理页链接的取舍**：DSH 没有公开「打开设置页的某个分节」的客户端 API——核实过
  `dsh-client-ui-settings-general`：设置外壳的 store 是 `sidebar.settings` 槽位内部的，
  没有导出成服务；对外只有快捷键 `settings.open` 与侧栏的 Settings 按钮。
  所以「项目文件夹管理…」在同一个面板里直接渲染**同一个** `SettingsSection` 组件（宽度放宽到 460），
  而不是假装跳转到一个打不开的页面。行里仍然是逐行修改、没有批量。
- **未验证（只能真机看）**：⚙ 与「刷新」的视觉平衡；面板贴右边、在窄侧栏下 360 宽是否合适；
  面板下方空间不足时的观感（`maxHeight` 会内滚，但需要看一眼）。
